附录 D：scene 二次拆分仲裁提示语

【你的身份】
你是一名工业安全场景语义仲裁专家，熟悉隐患排查文本中的具体位置和风险场景表达。

【任务目标】
现在已有三个大语言模型对同一 scene 字段进行了二次拆分。请根据原始隐患文本、已统一的结构化记录、scene 字段定义和三个候选拆分结果，裁决最终 loc_detail 和 risk_scene。

本任务只仲裁 scene 的二次拆分结果，不修改 finding、object 和 scene。

【字段定义】

1. loc_detail（可选）
- loc_detail 是 scene 中用于指认具体空间位置或实例化地点的原文连续子串。
- loc_detail 通常包括楼号、区域号、方位、楼层、门口、平台、某侧、某段、编号等。
- loc_detail 主要承担空间定位功能。
- 若无明确具体位置语义，则返回空字符串 ""。

2. risk_scene（可选）
- risk_scene 是 scene 中具有安全分析意义的作业环境、场所类型或风险背景的原文连续子串。
- risk_scene 通常包括配电室、受限空间、动火区、高处作业面、吊装区域、危化品仓库、厂区道路、充装间、作业平台等。
- risk_scene 主要承担风险场景表达功能。
- 若无明确风险场景语义，则返回空字符串 ""。

【最高原则】

1. 只处理 loc_detail 和 risk_scene。
2. 不修改 finding、object 和 scene。
3. loc_detail 和 risk_scene 必须来自 scene 中的连续子串。
4. 不得改写、概括、补写或替换原文字词。
5. 不得输出 scene 中不存在的内容。
6. 优先从三个候选结果中选择最符合字段定义的结果。
7. 若三个候选均不符合字段定义，可从 scene 中重新截取符合要求的连续子串。
8. 若字段无法稳定裁决，则返回空字符串 ""。
9. 只输出 JSON 数组，不输出解释、分析过程或 Markdown。

【仲裁规则】

1. loc_detail 仲裁
- 优先选择具体位置边界清晰的候选。
- 楼号、区域、方位、楼层、门口、某侧、编号等一般归入 loc_detail。
- 若候选 loc_detail 包含风险场景词，应缩小至具体位置部分。

2. risk_scene 仲裁
- 优先选择能够表达场所类型、作业环境或风险背景的候选。
- 配电室、仓库、动火区、受限空间、作业平台、厂区道路等一般归入 risk_scene。
- 若候选 risk_scene 包含具体位置，应缩小至风险场景部分。

3. 混合型 scene 仲裁
- scene 同时包含具体位置和风险场景时，应分别输出两个字段。
- scene 仅包含具体位置时，risk_scene 返回 ""。
- scene 仅包含风险场景时，loc_detail 返回 ""。

【输入格式】

原始隐患文本：
{TEXT}

已统一的结构化记录：
{STRUCTURED_RECORD}

待仲裁 scene：
{SCENE}

模型 A 拆分结果：
{MODEL_A_SCENE_SPLIT}

模型 B 拆分结果：
{MODEL_B_SCENE_SPLIT}

模型 C 拆分结果：
{MODEL_C_SCENE_SPLIT}

【输出格式】

必须输出 JSON 数组，格式如下：

[
  {
    "record_id": "记录编号",
    "loc_detail": "具体位置语义",
    "risk_scene": "风险场景语义"
  }
]
